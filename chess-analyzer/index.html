Décisions

Quatre arbitrages

le piège

Ce que cette architecture coûte. Puisque le rapport se reconstruit depuis le cache, toute donnée qu'il utilise doit être stockée au niveau de la partie. Deux fonctionnalités calculées ailleurs étaient mortes en production — avec des tests au vert.

1 M nœuds

Budgéter en nœuds, pas en temps. Une limite de temps donne un résultat différent selon la machine — le suivi de progression n'aurait plus de sens. Coût : 2,27 s par coup.

Wilson

Refuser les chiffres non soutenables. Une faiblesse n'est déclarée qu'à partir de douze occurrences et si sa borne inférieure de Wilson dépasse la cohorte. En dessous, l'application affiche qu'elle ne sait pas encore.

0 repli

Échouer plutôt que deviner. Sans Stockfish, l'analyse s'arrête. Un repli sur le comptage matériel donnerait une précision de 100 % — un rapport faux et parfaitement crédible.

Produit

Un rituel, pas un rapport

Le diagnostic devient une séance de dix minutes, renouvelée chaque jour.

Fiabilité

Comment je sais que ça marche

22 s

Deux niveaux de tests. Les unitaires rendent la main en 22 secondes — assez vite pour ne jamais hésiter à les lancer. Les tests d'intégration pilotent un vrai moteur et prennent dix minutes ; un marqueur sépare les deux, la CI exécute tout.

0

Constante magique. Probabilité de gain, seuils, précision, découpage des phases : chaque formule cite sa source primaire chez Lichess, en commentaire dans le code.

6

Défauts trouvés en pilotant l'app alors que 1 139 tests passaient : un bouton vers une route inexistante, une sonde de santé qui mentait, une fuite de données entre comptes. Ces bugs vivent dans les jointures, là où les tests unitaires ne vont pas.

Outils

Moteur

Stockfish piloté en UCI, multi-variantes, tables de finales Syzygy, livre d'ouvertures.

Traitement

Analyse parallélisée, cache versionné, file d'attente Celery pour les longues analyses.

Vérification

pytest sur deux niveaux, intégration continue, image Docker, audit documenté.
